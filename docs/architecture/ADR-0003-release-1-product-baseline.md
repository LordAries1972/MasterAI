# ADR-0003: Release 1 product and interoperability baseline

- Status: Accepted
- Decision date: 2026-07-28
- Applies to: MasterAI release 1

## Context

Phase 0 could not close while the operating-system, hardware, inference,
certificate, secret, attachment, voice, MCP, model-license, and benchmark
boundaries were left open. These decisions are release gates. Changing one
requires a new ADR, compatibility tests, and a migration or upgrade note.

## Decisions

### Supported operating systems

The release and CI matrix is:

- Windows 11 x86-64 and Windows Server 2022 x86-64.
- Ubuntu Server 24.04 LTS x86-64.
- Debian 13 (trixie) x86-64.

Other Linux distributions, ARM64, WSL, containers, and desktop-keyring-only
environments are buildable experiments, not supported release targets.
Production support ends when the distributor ends standard security support.

### Minimum hardware

- CPU: x86-64, SSE4.2, four logical processors.
- Memory: 16 GiB physical RAM, with at least 2 GiB reserved for the OS.
- Storage: 20 GiB free plus the declared model and backup footprint.
- GPU: optional. CPU inference is the compatibility baseline.
- GPU acceleration: a supported `llama.cpp` CUDA, Vulkan, or HIP build, at
  least 8 GiB dedicated VRAM, and a driver supported by that backend build.

AVX and AVX2 are detected and reported but are not release-1 minimums. A model
may impose stronger CPU/GPU requirements in its signed-off manifest; MasterAI
must reject it on lesser hardware.

### llama.cpp compatibility

Release 1 supports exactly upstream build `b10156`, commit `91f8c9c`, through
the `llama-server` process interface. The executable version must match before
it can be configured as an approved backend. A later build is unsupported
until its CLI, health, tokenization, streaming, cancellation, GGUF loading, and
resource-limit conformance suite passes. MasterAI never links model memory into
the control process.

### Intranet TLS certificates

The release-1 native listener is loopback-only. Intranet access terminates TLS
at an administrator-managed reverse proxy on the same host, using a certificate
issued by the organisation's private PKI or a publicly trusted CA. The proxy
connects to MasterAI over loopback. Self-signed leaf certificates generated by
MasterAI, plaintext intranet binding, wildcard host acceptance, and automatic
certificate trust installation are prohibited.

MasterAI still enforces authentication, host and origin allow-lists, request
limits, and CSRF behind that boundary. Direct non-loopback startup is rejected.

### Non-password secrets

OS passwords are transient inputs to Windows `LogonUserW` or Linux PAM and are
never secrets stored by MasterAI.

- Windows interactive/service installations use DPAPI-protected values scoped
  to the service identity. Only DPAPI ciphertext is persisted.
- Linux interactive installations use the service identity's kernel keyring.
- Linux system services receive persistent secrets through systemd encrypted
  credentials (`LoadCredentialEncrypted=`); MasterAI reads the credential from
  the service runtime directory and never copies it into its record store.

Unavailable OS protection fails closed. Tokens issued to IDE, Agent-Coder,
MCP, or model clients are random, scoped, revocable credentials, never OS
passwords.

### Attachments and voice

Release 1 accepts UTF-8 text, Markdown, JSON/JSONL, CSV, XML, YAML, unified
diffs, and recognised programming-language source files up to 16 MiB.
Executables, archives, office documents, PDFs, and ambiguous binary input are
rejected until a sandboxed parser is separately approved.

Voice input is optional and uses `whisper.cpp` v1.7.5, commit `51c6961`, through
an isolated adapter. The accepted interchange is PCM WAV, mono, 16 kHz,
16-bit. Voice is disabled when that exact backend and a verified Whisper model
are not configured.

### MCP revision

MCP is pinned to protocol revision `2025-11-25`. Supported transports are
newline-delimited UTF-8 JSON-RPC over `stdio` and Streamable HTTP. HTTP clients
must send `MCP-Protocol-Version: 2025-11-25`; invalid or unsupported revisions
receive HTTP 400. Legacy HTTP+SSE from `2024-11-05` remains disabled.

### Model licensing and provenance

Every model requires an immutable source revision, HTTPS source URL, exact file
size, SHA-256 digest, SPDX-style license identifier, and recorded administrator
acceptance. Release 1 accepts Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause,
CC-BY-4.0, and the explicitly named Llama 3.1, Llama 3.2, and Gemma terms.
Unknown, missing, custom, non-commercial, research-only, or field-of-use
restricted terms fail closed pending a policy update. Hugging Face and GitHub
are transport allow-list entries, not trust or license decisions.

### Benchmark data and metrics

The programming-quality baseline uses:

- HumanEval from `openai/human-eval` under MIT terms.
- MBPP from `google-research/google-research/mbpp` under CC-BY-4.0 dataset
  terms, retaining required attribution.
- A repository-owned regression suite containing only newly authored prompts
  and tests; every item records author, license, language, and immutable hash.

Imports are pinned by commit and stored with source, license, and suite hash.
Generated code runs only in the later approved execution sandbox.

Required quality metrics are compile rate, test pass rate, pass@1, failure and
timeout counts, and deterministic regression deltas. Required performance
metrics are prompt and generation tokens per second, time to first token,
end-to-end latency, peak resident memory, and model-load time. Comparisons are
valid only for the same host fingerprint, backend build, prompt-suite hash,
profile, context size, sampling settings, and concurrency.

## Consequences

Phase 0 has no open high-risk release-1 decision. Wider distribution support,
direct native intranet TLS, additional model licenses, binary attachments,
other speech engines, newer backend builds, and newer MCP revisions require
explicit compatibility and security work rather than silent best-effort use.
