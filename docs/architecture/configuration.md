# `settings.json` field reference

This is the authoritative, field-by-field reference for `config/settings.json`.
It is generated by reading `ConfigurationManager::load()`/`serialize()` in
[`src/config.cpp`](../../src/config.cpp) and the `AppConfig` defaults in
[`src/masterai.hpp`](../../src/masterai.hpp) directly — if this document and
the source ever disagree, the source is authoritative.

Every section below except `server`, `tls`, `auth`, `workspace`, and `models`
is optional: omitting an optional section entirely leaves every field in it at
its compiled default. Within a section that *is* present, every field listed
is mandatory unless marked "optional" — `ConfigurationManager::load()` rejects
both unknown fields (anywhere) and missing mandatory fields with a startup
error, rather than silently guessing a value.

Numeric fields show `(default; ceiling)` — the ceiling is a hard policy
maximum enforced at load time, not a recommendation. Paths (`runtimeRoot`,
`modelsRoot`, and any relative path elsewhere in this file) resolve against
**the directory holding `settings.json`**, not the process's working
directory — see `masterai runtime-root <settings>` / `masterai
models-root <settings>` if you need to confirm the resolved absolute path.

## `schemaVersion`

Must be the literal integer `1`. There is currently only one schema version;
this field exists so a future breaking change can detect and reject (or
migrate) an old file instead of misreading it.

## `server` (required)

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `host` | string | `"127.0.0.1"` | Listener bind address. Anything other than a loopback address (`127.0.0.1`, `::1`, `localhost`) is an "intranet" bind and pulls in the extra requirements below. |
| `port` | integer | `7070`; `65535` (min `1024`) | Listener TCP port. |
| `allowIntranet` | boolean | `false` | Must be `true` before a non-loopback `host` is accepted at all. |
| `maxRequestBytes` | integer | `16777216` (16 MiB); `67108864` (64 MiB) | Hard ceiling on a single HTTP request body. |
| `requestTimeoutSeconds` | integer | `30`; `300` | Per-request idle/read timeout. |
| `maxConcurrentConnections` | integer | `64`; `1024` | Hard ceiling on simultaneous accepted connections. |
| `rateLimitPerMinute` | integer | `120`; `100000` | Per-client request rate ceiling. |
| `allowedHosts` | array of strings, non-empty, unique | `["127.0.0.1","localhost"]` | `Host:` header allow-list; anything else is rejected before routing. |
| `allowedOrigins` | array of strings, unique | `[]` | `Origin:` allow-list used by CSRF/CORS checks. Only needs entries once a browser client is reached from another origin (e.g. through the reverse proxy an intranet bind requires). |

## `tls`(required)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `mode` | `"disabled-loopback-only"` \| `"required"` | `"disabled-loopback-only"` | `"required"` is mandatory the moment `server.host` is non-loopback. |
| `certificateFile` | string path | `""` | PEM certificate file. Required (and must exist) when `mode` is `"required"`. |
| `privateKeyFile` | string path | `""` | PEM private key file. Required (and must exist) when `mode` is `"required"`. |

MasterAI's own listener never terminates TLS for you in the loopback-only
default; the documented release-1 path for a non-loopback bind is an
administrator-managed reverse proxy in front of it (see the Configuration
section of the main [README](../../README.md)).

## `auth` (required)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `enabled` | boolean | `true` | Must be `true` — authentication cannot be disabled. |
| `sessionMinutes` | integer | `480` (8h); ceiling `10080` (7 days) | Session token lifetime. |
| `allowLocalPasswordAccounts` | boolean, optional | `true` | Locally stored, MasterAI-hashed password accounts (the default sign-in path — no external identity provider needed). |
| `allowOsIdentityAccounts` | boolean, optional | `false` | Opt-in OS-verified sign-in (`LogonUserW` on Windows, PAM on Linux). Can be enabled alongside local password accounts; both paths keep working together. |

## `workspace` (required)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `runtimeRoot` | string path | `"runtime"` | Durable state: projects, chats, attachments, indexes, cache, downloads, benchmarks, logs, backups. |
| `modelsRoot` | string path | `"models"` | Root of the categorized model tree (see the README's [Models](../../README.md#models) section). |

## `models` (required)

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `memoryReserveMiB` | integer | `2048`; `1048576` | RAM reserved for the control plane / OS before a model load is admitted. |

## `inference` (optional)

Omitting this section entirely — or leaving `llamaServerExecutable` blank —
disables inference; every chat request then fails with
`inference_backend_not_configured`.

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `llamaServerExecutable` | string path | `""` | Path to a version-pinned `llama-server` / `llama-server.exe`. MasterAI supervises it as a separate process; it does not vendor or build it. |
| `runnerPort` | integer | `7081`; `65535` (min `1024`) | Loopback port MasterAI's inference supervisor talks to the runner process on. |
| `chatMaxReplyTokens` | integer, optional | `16384`; `32768` | Ceiling on tokens generated per reply (`n_predict`). A safety cap, not a target length — generation still stops earlier at the model's own end-of-turn token or a configured stop sequence. |
| `chatContextLength` | integer, optional | `32768`; `1048576` | Total context window (`n_ctx`) the runner is launched with. **This must comfortably exceed a chat's full running total** — prior turns' history is resent every message (there is no automatic history truncation), plus the new turn, plus headroom for the reply. Once that total exceeds `chatContextLength`, the runner rejects the completion request (surfaced as `"runner generation request failed"`). Raise this — bounded by what your model supports and what your RAM/VRAM can hold for its KV cache — for long-running conversations. `131072` matches Llama 3.2's advertised maximum context. |
| `startupTimeoutSeconds` | integer, optional | `120`; `3600` | How long to wait for the runner's readiness probe after launch before declaring a cold load failed. Large models (e.g. DeepSeek-class) need more than the default. |

### GPU offload

There is no separate `inference.gpuLayers`-style setting: GPU-layer offload
(`--n-gpu-layers`) is decided automatically, per model load, from real
detected hardware (`select_gpu_layers()` in `src/calibration.cpp`) — a model
whose declared size comfortably fits the detected VRAM (minus a reserved
headroom for the backend's own context/runtime overhead) is offloaded in
full; otherwise CPU-only is kept as the always-safe default rather than
guessing a partial layer count. VRAM size is auto-detected on Windows via
DXGI. There is currently nothing to configure here beyond having a supported
CUDA/Vulkan/HIP driver installed and a model manifest whose
`requiredGpuBackend` (if any) matches it.

## `downloads` (optional)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `curlExecutable` | string path, optional | `""` | Approved `curl` executable. Blank disables `masterai download-model` and the download API/UI; models can still be placed under `modelsRoot` manually. |

## `knowledge` (optional)

Knowledge-document ingestion (RAG upload endpoint, `ml_knowledge.cpp`).
Parquet uploads are converted to text via a process-isolated DuckDB CLI
helper (rule 15's second named exception alongside `llama.cpp`) — never
vendored or linked, distributed separately, configured by filesystem path.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `parquetHelperExecutable` | string path, optional | `""` | Approved DuckDB CLI (`duckdb.exe`/`duckdb`) executable. Blank disables Parquet knowledge-document ingestion; other supported media types (text/Markdown/CSV/JSON/JSONL) are unaffected. |
| `maximumDocumentBytes` | integer | `26214400` (25 MiB); `268435456` (256 MiB) | Per-file size ceiling applied to every knowledge-document upload, replacing the previously hardcoded 2 MiB constant. |

## `research` (optional)

Phase 103, Web Research and Knowledge Acquisition (`research.cpp`). Queries
the official Google Custom Search / Bing Web Search APIs via the same
`curl`-subprocess path `downloads` above uses, scores results with an
editable reliability-tier table (`GET`/`POST
/api/v1/research/reliability-tiers`), and ingests relevant, reliable-enough
pages through the same `KnowledgeIndexStore::ingest()` the `knowledge`
section above configures. Off by default. API keys are **not** part of this
section — they are set write-only via `POST /api/v1/research/credentials`
and stored in `SecretStore`, never in `settings.json`.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `enabled` | boolean | `false` | Master on/off switch for the whole feature. |
| `googleEnabled` | boolean | `false` | Query the Google Custom Search JSON API (requires `googleEngineId` here and an API key set via the credentials endpoint). |
| `bingEnabled` | boolean | `false` | Query the Bing Web Search API (requires an API key set via the credentials endpoint). |
| `googleEngineId` | string | `""` | Google Programmable Search Engine id (`cx`) — not a credential. |
| `reliabilityThresholdPercent` | integer, 0-100 | `80` | Sources scored below this by the reliability-tier table are skipped without being fetched. The global reliability-threshold setting. |
| `maxResultsPerQuery` | integer, positive | `5` | Most results requested from each enabled provider per research run. |
| `maxPagesToFetch` | integer, positive | `5` | Most pages actually fetched (after reliability filtering) per research run. |
| `fetchTimeoutSeconds` | integer, positive | `20` | Per-request timeout for both search-API calls and page fetches. |
| `defaultSubjectId` | string | `""` | Subject a research request lands in when it doesn't specify one. |
| `defaultVectorStoreId` | string | `""` | Vector store a research request ingests into when it doesn't specify one. A request is rejected if neither this nor a request-supplied vector store id is set. |

## `indexing` (optional)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `watchProjectFiles` | boolean | `true` | Runs a native file-watcher/branch-switch adapter (`ProjectWatcher`) that requests an incremental reindex automatically on save or `.git/HEAD` change. Disabling this only turns off the automatic adapter — the authenticated index/notify/rebuild routes stay available either way. |

## `topology` (optional)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `numaLocalPlacementEnabled` | boolean | `false` | Phase 28: opt-in NUMA-local thread placement for per-connection worker threads. Off by default per the plan's "applied only where measurement shows benefit — not pinned by default"; `recommend_thread_placement()` also no-ops on any single-NUMA-node host regardless of this flag. Additionally gated at the call site by the Phase 20 `numa_affinity` Advanced Optimization admission (`POST /api/v1/performance/advanced-optimizations`) — both the evidence-backed admission and this flag are required before any thread is actually pinned to a NUMA node. |

## `modelRouting` (optional)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `tiers` | object of `string -> string[]` | `{}` | Phase 29: declares which registered model ids belong to each of the five `ModelTier`s (`deterministic_processing`, `compact_router`, `small_fast`, `medium_general`, `large_specialist`). Empty by default: the advisory `POST /api/v1/models/route` endpoint and the post-turn cascade-escalation audit entry both stay inert (no tier configured to select from) until an administrator declares at least one tier here. This is advisory routing only in this pass -- it never automatically switches a chat's model; see `docs/PLAN.md` Phase 29's status note. |

## `retrieval` (optional)

Deadline-bound hybrid retrieval, applied once per chat message before prompt
assembly. Disabling it leaves attachment-based context untouched.

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `enabled` | boolean | `true` | Master on/off switch for retrieval. |
| `deadlineMilliseconds` | integer | `1500`; `30000` | Hard wall-clock budget for one retrieval pass. |
| `maximumContextBytes` | integer | `16384` (16 KiB); `4194304` (4 MiB) | Ceiling on retrieved text injected into one prompt. |
| `maximumChunksPerSource` | integer | `6`; `256` | Ceiling on chunks contributed by any single retrieval strategy. |
| `maximumTotalChunks` | integer | `20`; `1024` | Ceiling on chunks across all strategies combined. |
| `semanticEmbeddingEnabled` | boolean | `true` | Opt-out for the `semantic_embedding` strategy (a `/v1/embeddings` backend round trip per candidate chunk). Only runs when a live embedding-capable runner is also configured. |
| `gitDiffEnabled` | boolean | `true` | Opt-out for the `git_diff` strategy (a sandboxed `git` subprocess). Silently produces no evidence when the project isn't a git working tree or `git` isn't installed. |
| `mcpResourceEnabled` | boolean | `true` | Opt-out for the `mcp_resource` strategy (reads from outbound MCP servers). Only runs for a requester whose scopes actually include `mcp.tools.invoke` on an authorized server. |

As of this pass every `RetrievalStrategy` has a real adapter (see
`docs/PLAN.md`'s Phase 16/24 status notes): `exact_symbol`, `exact_text`,
`lexical`, `filename_path`, `recent_change`, `call_graph`, `type_reference`,
and `dependency_neighbour` are always-on heuristic scans with no separate
toggle; `semantic_embedding`, `git_diff`, and `mcp_resource` are gated both
by the booleans above and by whether this MasterAI instance actually has the
underlying dependency wired in (an embedding-capable runner, the `git`
executable, or an authorized outbound MCP server respectively) —
`conversation_memory` has no toggle of its own since it only ever surfaces a
user's own previously recorded memories.

## `cache` (optional)

Security-partitioned cache in front of retrieval results (`CacheManager`).

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `enabled` | boolean | `true` | Master on/off switch for the retrieval-result cache. |
| `maximumBytesPerCategory` | integer | `67108864` (64 MiB); `4294967296` (4 GiB) | Per-category disk budget; segmented LRU eviction keeps each category under this. |

## `chatTools` (optional)

Bounds on the six built-in project tools (`read_file`, `list_directory`,
`search`, `write_file`, `delete_file`, `run_command`) shared verbatim by the
web-ui chat tool loop and by every MCP client (VS Code, Visual Studio, ...)
calling the same tools through `tools/call` -- see `execute_chat_tool()` in
`src/tool_exec.cpp`. Raising these lets the AI's directory listings,
searches, and command output come back more complete before being cut off;
lowering them trades that off against a single tool call being able to stall
the request thread longer or return a larger response.

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `readFileMaximumBytes` | integer | `1048576` (1 MiB); `268435456` (256 MiB) | Largest single file `read_file` will read; also the per-file size cutoff `search` applies before scanning a file's lines. |
| `searchMaximumFiles` | integer | `512`; `100000` | Most files `search` will walk before stopping. |
| `searchMaximumResults` | integer | `50`; `100000` | Most matching lines `search` will return. |
| `listDirectoryMaximumEntries` | integer | `4000`; `1000000` | Most files/folders `list_directory` will enumerate in one recursive tree walk before it reports the listing as truncated and asks for a narrower subdirectory. |
| `commandTimeoutSeconds` | integer | `30`; `3600` | How long `run_command` lets the sandboxed process run before it is killed as hung. |
| `commandMaximumOutputBytes` | integer | `262144` (256 KiB); `268435456` (256 MiB) | Most combined stdout/stderr bytes `run_command` will capture from one process before cutting it off. |

## `session` (optional)

Runner prompt-prefix / KV-cache session reuse (`PromptSessionManager`). Off
by default until its own same-host repeated-turn benchmark records exit
evidence (see [docs/PLAN.md](../PLAN.md) Phase 18).

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `enabled` | boolean | `false` | Whether reuse is attempted at all. |
| `maxSlots` | integer | `4`; `64` | Number of parallel KV-cache slots the runner is launched with. |
| `idleRetentionSeconds` | integer | `300`; `86400` | How long an idle slot's cached prefix is kept before eviction. |

## `performance` (optional)

| Field | Type | Default | Meaning |
|---|---|---|---|
| `autoTune` | boolean | `true` | Whether `POST /api/v1/performance/calibrate` is permitted to run at all. The profile a calibration run measures against is `memory.profile` above (plus an `"auto"` option accepted only at calibrate-request time, never persisted). |

## `memory` (optional)

System-wide memory admission (`MemoryBudgetManager`). If this section is
present, all four fields below are mandatory.

| Field | Type | Default; ceiling | Meaning |
|---|---|---|---|
| `hardLimitMiB` | integer, non-negative | `0`; `1048576` | Absolute RAM ceiling for everything MasterAI admits. `0` means no explicit hard limit (the OS-reserve and percentage fields below still apply). |
| `minimumFreePercent` | integer | `15`; `50` | Percentage of total RAM kept free as an OS safety reserve; admission is refused before this is breached. |
| `criticalPressurePercent` | integer | `92`; `99` | Percentage of RAM in use at which MasterAI starts taking pressure-relief action (see `docs/PLAN.md` Phase 14). |
| `profile` | `"minimal"` \| `"balanced"` \| `"performance"` | *(no compiled default — required whenever this section is present)* | Governs both `MemoryBudgetManager`'s admission profile and, via `CalibrationService`, which safe-default `TuningProfile` an uncalibrated model load starts from. |

## Environment variable overrides

A small, fixed set of settings can be overridden without editing the file —
see [Configuration](../../README.md#configuration) in the main README for the
full precedence order and the list of supported `MASTERAI_*` variables.
Anything not on that list has no environment override; edit `settings.json`
(or re-run `scripts/configure.ps1` / `scripts/configure.sh`) instead.
